# **2교시: 받는 쪽이 된다 (폴링 vs 웹훅)**

## **1. 개념 잡기: 폴링(Polling)과 웹훅(Webhook)**

데이터를 가져오는 방법은 크게 두 가지가 있습니다. 

- **폴링 (Polling):** 내가 주기적으로 **"새로운 일 있어?"** 하고 계속 물어보는 방식이에요.
    - *문제점:* 아무 일도 없을 때도 계속 물어봐야 하니 **네 번이나 헛걸음(자원 낭비)**을 하게 되죠. 자주 물어보면 서버가 힘들어하고, 늦게 물어보면 경보를 늦게 알게 되는 딜레마가 있습니다.
- **웹훅 (Webhook):** 나는 가만히 기다리고, 상대방이 **"일 터졌다!"** 하고 먼저 알려주는 방식이에요. 헛걸음할 필요가 없어서 훨씬 효율적이죠!

## **2. 파이썬으로 서버 만들기 (Flask)**

웹훅을 받으려면 상대방이 찾아올 수 있는 '주소'와 요청을 기다리는 '서버' 프로그램이 있어야 해요. 파이썬에서는 **Flask**라는 아주 가볍고 강력한 도구를 사용합니다. 

기본적인 웹훅 서버 코드는 아래와 같이 생겼어요.

```python
from flask import Flask, request

app = Flask(__name__)

# /webhook 이라는 주소로 POST(보내기) 요청이 오면 아래 함수를 실행해라!
@app.route("/webhook", methods=["POST"])
def webhook():
    event = request.get_json()  # 상대방이 보낸 데이터를 딕셔너리로 받기
    return {"status": "ok"}, 200  # 잘 받았다고 성공 코드(200) 돌려주기

```

### **💡 선생님의 핵심 요약 노트 (`2교시 한눈에`)**

- **서버는 항상 켜져 있는 프로그램**이라 노트북 셀에서 실행하면 셀이 끝나지 않고 멈춰있어요. 그래서 우리는 `start_server()`라는 도우미 함수를 써서 백그라운드로 돌리는 거랍니다.
- `@app.route("/주소")` 문법은 특정 주소로 들어온 요청을 아래에 있는 함수와 **연결(라우팅)**해주는 다리 역할을 해요.
- 상대방이 보낸 데이터는 `request.get_json()`으로 꺼내서 파이썬 딕셔너리처럼 요리하면 됩니다!

**1. `app.run(port=5006)` 이란?**

> **비유: "우리 집 5006호 문 열어놓고 손님 올 때까지 하루 종일 기다려!"**
> 

우리가 Flask로 코드를 짜는 건 "손님이 오면 이렇게 행동해라"라는 **규칙**을 정한 것뿐이에요. 이 규칙을 실제로 행동으로 옮기게 하는 스위치가 바로 `app.run()`입니다.

- **포트(port) 번호는 문 번호예요:** 컴퓨터에는 수많은 프로그램이 돌고 있어서 문이 여러 개 필요해요. `port=5006`은 **"우리 서버는 5006번 문 앞에서 손님을 기다릴게"**라고 지정해 주는 거랍니다.
- **끝나지 않는 프로그램:** 서버는 손님이 언제 올지 모르니까 **24시간 내내 대기**해야 하죠? 그래서 `app.run()`을 실행하면, 프로그램이 끝나지 않고 계속 그 자리에 멈춰서 손님(요청)을 기다리게 됩니다.

# **3교시: 손으로 두드린다 (curl과 셸 스크립트)**

## **1. 개념 잡기: CLI와 GUI, 그리고 `curl`**

- **GUI (Graphic User Interface):** 마우스로 아이콘이나 버튼을 딸깍딸깍 누르는 방식이에요 (예: 인터넷 브라우저).
- **CLI (Command Line Interface):** 마우스 없이, 오직 **검은 창에 글자(명령어)**만 타이핑해서 컴퓨터를 조종하는 방식이에요. 개발자들은 이 방식을 훨씬 많이 씁니다.
- **`curl` 이란?**터미널창(CLI)에서 다른 서버에 **"야, 데이터 받아라!" 하고 요청을 보내는 명령어**예요. 우리가 2교시에 만든 웹훅 서버에 노크를 하려면 이 `curl` 명령어가 필요해요.

## **2. `curl` 명령어를 구성하는 세 조각 (옵션)**

웹훅 요청을 보낼 때는 딱 3가지만 기억하면 돼요. 9/29 수업 때 배웠던 내용이 옵션 이름으로 그대로 들어갑니다.

| **옵션** | **무엇을 뜻하나요?** | **예시** |
| --- | --- | --- |
| **`-X`** | **메서드** (데이터를 어떤 방식으로 보낼 것인가) | `-X POST` (보내겠다) |
| **`-H`** | **헤더** (내가 보내는 데이터의 형식이 무엇인가) | `-H "Content-Type: application/json"` (JSON 형식이야) |
| **`-d`** | **본문(데이터)** (진짜 보낼 알맹이 내용) | `-d '{"rule": "brute_force"}'` (경보 내용) |

그래서 터미널에 입력할 최종 명령어는 이렇게 생겼어요.

```bash
curl -X POST -H "Content-Type: application/json" -d '{"rule":"brute_force"}' http://127.0.0
```

*(맨 뒤의 주소는 2교시에 열어둔 5001번 문으로 가겠다는 뜻이에요!)*

(※ `-s -o /dev/null -w "%{http_code}"`는 "복잡한 본문은 버리고, 결과 상태코드만 깔끔하게 보여줘!"라는 옵션이에요.)

서버가 잘 받았다고 `{"status":"ok"}`라는 메시지를 돌려줌

**📍 문제 3-7: 매번 치기 귀찮으니 파일로 묶자 (`test_webhook.sh`)**

경보 종류가 3개인데 매번 터미널에 이 긴 명령어를 손으로 치면 오타가 나겠죠? 그래서 메모장에 명령어들을 줄줄이 적어놓고, 파일 한 번만 실행하면 주르륵 실행되게 만들 거예요. 이걸 **셸 스크립트(.sh)**라고 부릅니다.

*(※ 줄 끝에 있는 `\` 기호는 "명령어가 길어서 다음 줄로 이어져요"라는 뜻이고, `echo`는 결과 화면에서 줄바꿈을 이쁘게 해주려고 넣는 거예요.)*

이렇게 파일을 만들고 나면, 터미널에서 `bash test_webhook.sh`라고 딱 한 줄만 치면 세 가지 경보가 서버로 동시에 슝슝슝 날아갑니다!

### **💡 선생님의 핵심 요약 노트 (`3교시 한눈에`)**

- **`404`** 상태코드가 뜨면? ➡️ "너 주소 오타 났어! (그런 주소 없음)"
- **`405`** 상태코드가 뜨면? ➡️ "거기 주소는 맞는데, GET이 아니라 POST로 보내야 해! (메서드 틀림)"
- **`415`** 상태코드가 뜨면? ➡️ "헤더에 JSON 형식이라고 안 적어줘서 안 받아! (형식 에러)"
- **`200`** 상태코드가 뜨면? ➡️ **성공!** 아주 완벽하게 잘 갔다는 뜻입니다.

- 수업 메모
    
    curl은 HTTP 요청을 전송하고 응답 본문을 출력함.
    
    ```bash
    curl -s -X POST -H "Content-Type: application/json" \
      -d '{"rule":"brute_force"}' http://127.0.0.1:5001/webhook
    ```
    
    - curl: 서버에 요청을 보내는 도구
    - -s: 진행 상황을 화면에 표시하지 않음
    - -X POST: 데이터를 보내는 방식으로 요청 (HTTP 메서드 지정)
    - -H “Content-Type: application/json”: header의 약자. 보내는 내용이  json임을 알림. 생략하면 415 에러코드
    - \ : 명령이 다음줄에 이어진다는 표시
    - -d ‘{}’: data의 약자. rule에 night_login을 담아 보냄. 요청 본문을 지정
    - 작은따옴표: json 전체를 감쌈
    - 큰따옴표: JSON 안의 이름과 값을 감쌈. json은 큰따옴표만 허용
    
    ```bash
    curl -s -o /dev/null -w "%{http_code}" \
    	http://127.0.0.1:5001/webhook
    	
    405
    ```
    
    - -o /dev/null: 응답 본문은 출력하지 않고 상태 코드만 출력
    
    오류를 나타내는 상태 HTTP 코드
    
    - 404 — 요청한 경로가 없다.
    - 405 — 경로는 있지만 요청 메서드가 허용되지 않는다
    - 415 — 서버가 요청 본문 형식을 처리할 수 없다
    
    ```bash
    save_script("test_webhook.sh", r"""
    curl -s -X POST -H "Content-Type: application/json" \
      -d '{"rule":"brute_force"}' http://127.0.0.1:5001/webhook
    echo
    curl -s -X POST -H "Content-Type: application/json" \
      -d '{"rule":"night_login"}' http://127.0.0.1:5001/webhook
    echo
    """)
    ```
    
    - echo : 빈 줄을 출력. 응답 두개가 붙어보이지 않게 함.
    - `save_script("파일이름", r"""…""")` 는 따옴표 세 개 사이의 내용을 그 파일로 저장합니다. 맨 위 준비 셀에 있는 함수입니다.

# **4교시: 설정을 밖으로 (`argparse` 배우기)**

우리가 2교시 때 만든 서버는 코드 맨 밑에 `app.run(port=5001)` 이런 식으로 포트 번호가 파일 안에 고정되어 있었어요. 이러면 포트를 바꾸고 싶을 때마다 메모장이나 VS Code로 소스코드를 열어서 숫자를 수정해야 하니까 아주 귀찮고 위험해요.

그래서 **"코드는 가만히 두고, 프로그램을 실행할 때 까만 창(터미널)에서 포트 번호를 던져주자!"**라는 아이디어가 나온 거예요. 이걸 도와주는 파이썬 기본 도구가 바로 `argparse`랍니다.

---

```python
import argparse

# 명령어 해석기 (parser)를 하나 새로 만듦 / description은 이 프로그램 소개글
parser = argparse.ArgumentParser(description="경보를 받는 웹훅 서버")

# 해석기한테 "앞으로 사용자가 --port라고 말하고 뒤에 숫자를 붙여서 실행할 수 있게 규칙을 추가해줘"라고 명령 / help는 인자 설명서
parser.add_argument("--port",type=int, default=5000,help="열어 둘 포트 번호")

# 사용자가 터미널에 입력한 명령어 읽어 해석 -> 결과물을 args에 저장
args = parser.parse_args()

# 방금 해석해서 알아낸 포트 번호(args.port)를 화면에 출력
print(args.port)
```

- `--help` 를 붙이면 **적어 둔 설명이 그대로** 나옴.

# **5교시: 코드를 '트리거·조건·액션' 세 조각으로 쪼개기**

우리가 그동안 만들었던 프로그램(로그 분석기, API 요청기 등)은 겉보기엔 다 제각각으로 생겼어요. 하지만 가만히 뜯어보면 **모든 자동화 프로그램은 딱 이 3단계 구성**으로 이루어져 있습니다.

1. **트리거 (Trigger) : "~할 때" (시작 신호)**
    - 어떤 사건이 일어나야 프로그램이 깨어날 것인가?
    - 예시: "새로운 로그 파일이 들어왔을 때"
2. **조건 (Condition) : "~라면" (판단 기준)**
    - 들어온 데이터를 보고 알림을 보낼 만한 상황인지 검사하는 단계
    - 예시: "로그인 실패 횟수가 3번 이상이라면?"
3. **액션 (Action) : "~해라" (실제 행동)**
    - 조건이 맞을 때 수행하는 최종 임무
    - 예시: "보안 담당자에게 '해킹 위험!'이라고 경보(Alert)를 보낸다"

---

**💡 왜 굳이 귀찮게 세 조각으로 나눠서 코딩할까요?**

과외학생들이 많이 하는 질문이에요. "선생님, 그냥 한 통으로 길게 짜면 안 돼요?"

물론 되지만, 나중에 코드를 수정할 때 대공사가 일어나요. 예를 들어, 보안 팀장이 와서 **"야, 알림 방식을 이메일에서 슬랙(Slack) 메시지로 바꿔줘"**라고 했다고 해볼게요.

- **나누지 않은 코드:** 처음부터 끝까지 훑으며 어디를 고쳐야 하는지 헤매야 함.
- **나눈 코드:** 다른 곳은 안 건드리고 **'액션' 조각만 쏙 고치면 끝!**

코드가 엄청나게 깔끔해지고 유지보수가 편해집니다.

### requests.post() 함수

`requests.post()` 함수는 파이썬에서 **외부 서버로 데이터를 보낼 때(전송할 때) 사용하는 가장 대표적인 도구**예요.

우리가 인터넷창에 주소를 치고 엔터를 누르는 것은 정보를 가져오는 'GET' 요청이라면, `requests.post()`는 글을 쓰거나 로그인 정보를 제출하는 것처럼 서버에 데이터를 밀어 넣는 **'POST' 요청**을 날리는 역할을 합니다.

```python
import requests

URL = "http://127.0.0"
event = {"rule": "brute_force", "user": "admin"}

# 🚀 외부 서버로 경보 데이터 전송하기!
response = requests.post(URL, json=event, timeout=5)
```

이 한 줄에 들어있는 인자(배달 조건)들의 의미는 다음과 같습니다.

1. **`URL` (어디로 보낼 것인가?)**
    - 데이터가 도착할 목적지 주소예요. 오전에 미리 켜둔 웹훅 수신 서버 주소인 `http://127.0.0`을 적어 준 것입니다.
2. **`json=event` (무엇을 보낼 것인가?)**
    - **가장 중요한 부분이에요!** 우리가 만든 경보 내용(`event` 딕셔너리)을 서버가 이해하기 쉬운 **JSON 형식의 본문(Body)**에 담아서 포장해 보내겠다는 뜻입니다.
3. **`timeout=5` (얼마나 기다릴 것인가?)**
    - "인터넷이 느리거나 서버가 먹통이면 최대 5초까지만 기다리고 포기해!"라는 안전장치예요. 이게 없으면 서버가 응답하지 않을 때 프로그램이 영원히 멈춰 버릴 수 있어요.

---

**📦 보내고 난 뒤에는 어떻게 되나요? (`response`)**

택배를 보내면 영수증을 받듯이, `requests.post()`를 실행하면 서버가 준 응답이 `response`라는 변수에 저장돼요.

```python
# 서버가 돌려준 답변(JSON)을 파이썬 딕셔너리로 변환해서 꺼내 쓰기
result = response.json() 
print(result["status"])  # 화면에 'ok'가 출력됨
```

서버는 무사히 잘 받았다는 의미로 `{"status": "ok", "count": 1}` 같은 영수증을 돌려주고, 우리는 `.json()` 문법을 통해 그 답변을 파이썬에서 요리조리 요리해서 쓸 수 있게 됩니다.

# 6교시: '멱등성(Idempotency)'과 '중복 알림 방지’

## **1. 왜 멱등성이 필요할까? 🤦‍♂️**

만약 우리가 만든 프로그램이 5분마다 자동으로 실행되면서 로그 파일을 검사한다고 가정해 볼게요.그런데 파일에 기존 로그가 그대로 남아있다면, 프로그램은 다음 실행 때도 똑같은 위협 로그를 보고 **또 알림**을 보내게 됩니다. 하루면 무려 288번이나 같은 알림이 가는 셈이죠. 

이렇게 같은 알림이 반복해서 가다 보면 사람은 무뎌져서 결국 **아무도 안 보게 되고**, 정작 중요한 진짜 경보가 그 사이에 묻혀버리는 심각한 보안 문제가 생깁니다.

그래서 개발할 때 아주 중요한 개념이 등장합니다.

> **멱등성(Idempotency):** 똑같은 일을 두 번, 세 번 여러 번 수행하더라도, 결과는 단 한 번 수행한 것과 같아야 하는 성질을 말해요.
> 

즉, **"이미 처리해서 보낸 경보는 기억해 두었다가 다시 보내지 않겠다"**는 뜻입니다.

---

## **2. 중복을 막는 핵심 메커니즘**

6교시 실습에서는 이 중복을 막기 위해 **두 가지** 장치를 만들었어요.

**① 사건 번호 (ID) 부여하기**

경보마다 주민등록번호 같은 고유한 이름을 붙여줍니다. 예를 들어 `brute_force:admin`처럼 **[룰 이름:공격 계정]**을 조합해서 ID를 만드는 식이죠. 같은 사건이라면 언제 실행하더라도 무조건 똑같은 ID가 나와야 합니다.

**② 파일에 기억하기 (`processed_ids.json`)**

보낸 경보의 ID 목록을 파이썬 프로그램의 메모리(리스트)에만 담아두면, 프로그램이 종료되는 순간 싹 사라져 버립니다. 5분 뒤에 다시 켜졌을 때 기억을 유지하려면 하드디스크의 **파일**에 영구적으로 적어두어야 합니다.그 기록 장부가 바로 `processed_ids.json` 파일입니다.

## **3. 코드로 보는 장부 관리법**

프로그램이 켜지면 제일 먼저 장부를 읽고, 일이 끝나면 장부를 업데이트해서 저장합니다. 

- **장부 읽기 (`load_done`):**`os.path.exists()` 명령어로 먼저 장부 파일이 있는지 확인해요. 처음 실행할 때는 파일이 없으니 빈 리스트(`[]`)를 반환하고, 파일이 있으면 `json.load()`로 예전에 저장해둔 보낸 ID 목록을 가져옵니다.
- **중복 검사 (`not in`):**새로운 경보가 발생하면 `if event["id"] not in done:` 문법을 사용해 예전에 보낸 장부에 있는지 검사합니다. 장부에 없다면 처음 발견한 위협이니 전송 처리를 하고 장부에 ID를 추가(`append`)해 줍니다.
- **장부 저장 (`save_done`):**모든 처리가 끝나면 업데이트된 장부를 `json.dump()`를 이용해 다시 `processed_ids.json` 파일에 깔끔하게 덮어써서 보관합니다.

이렇게 구현하면, 두 번째 실행할 때부터는 장부 파일에 ID가 기록되어 있기 때문에 새로 발생한 위협이 없다면 **"보낸 건수: 0건"**이 나오며 완벽하게 중복 알림을 막아냅니다(멱등성 달성!).

### 딕셔너리에서 키가 존재하는지 확인하는법

`in` 연산자 사용 (가장 추천)

```python
my_dict = {"name": "Alice", "age": 25}

# 키 존재 여부 확인

    print("키가 존재합니다.")

```

# **7교시: 실행 버튼을 없앤다 (자동화)**

## **1. 스케줄러(Scheduler)가 왜 필요할까요?**

- **문제 상황:** 지금까지 우리가 만든 훌륭한 해킹 탐지 프로그램들은 전부 **사람이 마우스로 실행 버튼을 누르거나 터미널에 명령어를 입력해야만** 작동했습니다.
- 하지만 해커들은 우리가 퇴근한 새벽 3시에도 공격을 시도하죠. 그때 침대에 누워있는 우리 대신 프로그램을 실행해 줄 존재가 바로 **스케줄러**입니다.
- 방법은 크게 두 가지가 있습니다.
    1. **파이썬 안에서 실행하는 것:** `schedule` 패키지 사용.
    2. **운영체제(OS)가 실행하는 것:** `cron` 도구 사용.

---

## **2. 파이썬 안에서 도는 스케줄러: `schedule` 패키지 (7.1)**

파이썬의 `schedule` 라이브러리는 사람이 읽기 아주 쉬운 문장 형태로 코드를 짤 수 있는 게 장점입니다.

```python
import schedule
import time

def job():
    print("점검합니다")

# 1. 2초마다 job 이라는 함수를 실행하도록 스케줄러 목록에 등록합니다.
schedule.every(2).seconds.do(job)

# 2. 실습을 위해 딱 6번(6초 동안)만 반복하면서 스케줄러를 확인합니다.
for i in range(6):
    
    # 3. 현재 시각을 확인하여, 등록된 작업(2초 주기) 중 실행할 시간이 된 작업이 있다면 지금 실행합니다.
    schedule.run_pending()
    
    # 4. CPU 과부하를 막고 실제로 시간이 흘러가도록 프로그램을 1초 동안 멈추고 대기합니다.
    time.sleep(1)
```

반드시 아래에서 **`schedule.run_pending()`을 주기적으로 계속 호출해 줘야함.**

## 3. 컴퓨터가 꺼져도 OS가 실행해준다: **`cron`** 다섯 칸

`schedule` 패키지는 치명적인 약점이 있습니다. **그 파이썬 프로그램이 켜져 있는 동안만** 작동한다는 점이죠. 창을 닫거나 컴퓨터를 끄면 멈춥니다 [schedule, 창을].반면, 리눅스/맥 운영체제 자체에 내장된 `cron`은 프로그램이 종료되어 있어도 정해진 시각에 운영체제가 깨워서 실행해 줍니다.

`cron`은 빈칸으로 나뉜 **다섯 칸(분 시 일 월 요일)**으로 시간을 표현합니다.

- `0 6 * * *` → 분이 0, 시가 6이고 나머지는 별표(매번)이므로 **매일 오전 6시 정각**
- `/5 * * * *` → 분 자리에 `/5`가 있으므로 **5분마다** 실행
- 요일은 `0`이 일요일이며, 금요일은 `5`가 됩니다.
- *(주의: `cron`은 리눅스/맥용이라 윈도우에는 없습니다. 윈도우는 '작업 스케줄러'를 씁니다.*
