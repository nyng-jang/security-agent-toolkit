# **아침 과제 7 · 명령어로 깃허브에 올리기**

---

- git 으로 올릴 때는 왜 `add` · `commit` · `push` 세 단계로 나눌까요?
`git add commit push 차이`, `git 커밋 이란`
    - Git이 세 단계로 나누어진 이유는 작업 내용을 선택적으로 관리하고, 으미ㅣ있는 단위로 기록해 원격 저장소에 안정적으로 공유하기 위함.
    1. `add` (장바구니 담기 / stage) 
        1. 변경된 여러 파일 중 이번에 저장할 파일만 골라담기
        2. 파일 수정 작업 중 일부 완료된 파일만 먼저 골라낼 수 있음.
    2. `commint` (포장 및 세이브 포인트 생성)
        1. add로 골라 담은 파일들을 커밋 메시지와 함께 로컬의 기록으로 저장
        2. 작업 단위별로 세이브 포인트를 만들어두면 나중에 특정 시점으로 돌려보기 쉬움
    3. `push` (원격 업로드)
        1. 내 컴퓨터에 저장된 커밋 기록을 GitHub 같은 원격 저장소로 올려서 다른 사람들과 공유
- commit (커밋)
    - 무엇을 남기는가: 작업한 코드의 변경 이력을 남김
    - 왜 메시지를 함께 적나: 나중에 코드를 다시 보거나 팀원이 볼 때 ‘어떤 이유로 무엇을 수정했는지’ 한눈에 파악하기 위해서. 메시지 없으면 과거 코드의 변경 원인 알기 어려움.
- push(푸시)
    - 내 PC의 무엇을 어디로 보내는가: 내 컴퓨터(로컬 저장소)에 쌓아둔 commit 기록들을 깃허브같은 온라인 원격 저장소로 보냄.

## **`git status` 가 보여 주는 세 가지 상태**

> **untracked · tracked · staged**
> 

`git status` 의 결과는 영어 제목 아래에 파일을 나눠 보여 줍니다. 제목은 **세 가지**입니다. 이 셋만 읽을 줄 알면 「지금 무엇이 올라가고 무엇이 안 올라가는지」를 알 수 있습니다.

| **상태** | **읽는 법 · 뜻** | **`git status` 의 제목** | **색** | **이 파일은 지금** |
| --- | --- | --- | --- | --- |
| **untracked** | 언트랙트 · 추적하지 않는 | `Untracked files:` | 빨강 | git 이 **한 번도 기록한 적 없는 새 파일**입니다. 커밋에 들어가지 않습니다 |
| **tracked**, 바뀜 | 트랙트 · 추적하는 | `Changes not staged for commit:` (`modified:`) | 빨강 | 전에 커밋한 파일인데 **그 뒤에 고쳤습니다.** 고친 내용은 아직 커밋에 들어가지 않습니다 |
| **staged** | 스테이지드 · 다음 커밋에 넣기로 고른 | `Changes to be committed:` | 초록 | `git add` 로 고른 파일입니다. **다음 `git commit` 에 이 파일들만** 들어갑니다 |
- **tracked(트랙트)** 는 「git 이 이 파일을 기억하고 있다」는 뜻입니다. 한 번이라도 커밋된 파일은 모두 tracked 입니다. 9/30 부터 웹 화면으로 올린 파일도 tracked 입니다. 그 뒤에 고치면 git 이 알아채고 `modified:`(모디파이드 · 고쳐짐)로 보여 줍니다. 고치지 않았으면 `git status` 에 나오지 않습니다.

    - 프로그램 동작 방식 바꿀 때 소스코드 건드리지 않고 설정 파일만 수정하면 됨.

## JSON 파일 읽기와 쓰기

### 파일 읽기 `json.load`

: 파일을 읽어와 파이썬 딕셔너리로 변환.

```python
with open("config.json", encoding="utf-8") as f:
    config = json.load(f)  # config는 이제 딕셔너리가 됨
print(config["model"])    # 키를 이용해 값 꺼내기
```

### 파일 저장 `json.dump`

: 딕셔너리를 JSON 파일로 저장. 사람이 읽기 좋게 들여쓰기(indent=2) 해주는 게 좋음.

```python
json.dump(config, f, ensure_ascii=False, indent=2)
```

## 딕셔너리에서 **`in`** 연산자 활용

: 딕셔너리에 특정 키(Key)가 존재하는지 검사할 때 `in`과 `not in`을 사용

```python
config = {"model": "gemini-3.5-flash-lite"}

print("model" in config)        # True (키가 있으므로)
print("webhook_url" not in config) # True (키가 없으므로)
print("gemini-3.5-flash-lite" in config) # False (값이기 때문에 찾지 못함)
```

## 딕셔너리와 JSON 파일의 차이

```python
import json
print(json.dumps({"on":True,"url":None}))
# {"on": true, "url": null}
```

| **파이썬** | **JSON 파일** | **차이** |
| --- | --- | --- |
| `True` · `False` | `true` · `false` | 소문자 |
| `None` | `null` | 이름이 다르다 |
| `'작은따옴표'` 도 된다 | `"큰따옴표"` 만 된다 | `json.dump` 가 알아서 바꾼다 |

⚠ JSON 파일에는 주석(`#`)을 쓸 수 없습니다. 설명은 코드나 노트북에 둡니다.

# 3교시: 알림 연동

<aside>
❔

- 웹훅(Webhook) 알림: 보고서가 자동으로 완성되었을 때, 담당자가 매번 확인하러 오는 것이 아니라 슬랙(Slack), 팀즈(Teams), 혹은 사내 알림 시스템으로 프로그램이 먼저 알림을 쏴주는 방식
- 장애 허용(Fault Tolerance)
    
    만약 알림을 보내야 하는데, 알림 서버가 네트워크 오류나 점검으로 인해 잠시 꺼져 있다면?
    
    - 예외 처리가 없을 때: `ConnectionError` 발생, 그 자리에서 강제 종료. 앞 단계에서 만든 보고서 날아갈 수 있음
    - 장애 허용(예외 처리): 알림이 실패하더라도 "알림은 실패했다"고 기록만 남기고, 다음 단계(보고서 저장 등)로 안전하게 넘어가도록 만드는 것. → `try`와 `except`
</aside>

#### `requests.post` 의 `json=` 과 `timeout=`

```python
response = requests.post(url, json={"text":"알림"}, timeout=5)
print(response.status_code)# 200 — 받았다는 뜻
```

| **쓰는 것** | **뜻** |
| --- | --- |
| `url` | 보낼 주소. 오늘은 `config["webhook_url"]` 에서 꺼낸다 |
| `json={"text": …}` | 딕셔너리를 JSON 으로 바꿔 요청 몸통에 담는다 (9/30) |
| `timeout=5` | 5초 안에 답이 없으면 기다리지 않고 에러를 낸다 |

⚠ `timeout` 이 없으면 서버가 답을 주지 않을 때 셀이 끝나지 않고 멈춰 있습니다.

### with open “a”

Python에서 파일 끝에 내용을 덧붙이기(Append) 위해 `with open` 문을 사용할 때 발생할 수 있는 주요 문법 오류와 올바른 사용법입니다.

```python
with open("filename.txt", "a", encoding="utf-8") as f:
    f.write("덧붙일 내용\n")
```

#### `except Exception as e` — 에러를 잡아 이름 보기

```
try:
int("abc")
except Exceptionas e:
print("잡음:",type(e).__name__)
# 잡음: ValueError
```

| **쓰는 것** | **잡는 것** |
| --- | --- |
| `except ValueError:` | 그 에러 하나만 (9/28) |
| `except Exception as e:` | 거의 모든 에러. 잡은 에러가 `e` 에 담긴다 |
| `type(e).__name__` | 에러의 이름 — `ValueError` · `ConnectionError` |

#### 폴더 만들기와 경로 잇기

```python
os.makedirs("reports", exist_ok=True)# 이미 있어도 에러가 나지 않는다
print(os.path.join("reports","daily_report_20261008.md"))
# Windows: reports\daily_report_20261008.md   ·Mac: reports/daily_report_20261008.md
```

| **쓰는 것** | **하는 일** |
| --- | --- |
| `os.makedirs(폴더, exist_ok=True)` | 폴더를 만든다. 있으면 그냥 지나간다 |
| `os.path.join(폴더, 파일)` | 그 컴퓨터에 맞는 구분 기호로 경로를 잇는다 |
| `shutil.copy(원본, 새 경로)` | 파일을 복사한다 |

⚠ `"reports/" + filename` 처럼 직접 이으면 Windows 와 Mac 에서 모양이 달라집니다. `os.path.join` 을 씁니다.

### `os.path.exists(path)` 문법

```python
import os

# 파일 또는 폴더 경로 지정
path = "example.txt"

    print("경로가 존재합니다.")
else:
    print("경로가 존재하지 않습니다.")
```
