- (가) 회선 X 와 Y 의 평균 지연과 지터(이웃한 두 값의 차이의 평균), 회선 Z 의 손실률을 각각 구해 적어 주세요.
  - 쓸 내용: 「X: 평균 … ms · 지터 … ms / Y: 평균 … ms · 지터 … ms / Z: 손실 … %」


### 문제 6-2 · 세 회선을 화상회의 기준으로 판정하기

- (가) 세 회선의 판정 결과(적합 · 부적합)와 걸린 기준을 각각 적어 주세요.
  - 쓸 내용: 「A: … / B: … (걸린 기준 …) / C: … (걸린 기준 …)」
  - 답: A: 적합 / B: 부적합 (걸린 기준: 지터) / C:부적합 (걸린 기준: 손실)
- (나) 회선 C 는 지연과 지터가 작은데도 왜 부적합인가요? 어제(10/15) 오후 문제 5-2 에서 본 것과 연결해 적어 주세요.
  - 쓸 내용: ① C 의 손실률과 기준 ② 손실이 통신에 주는 영향 한 가지
  - 답: 회선 C의 손실률은 30%로, 기준인 1% 이하를 초과한다. 패킷 손실이 높으면 음성이나 영상이 끊길 수 있기 때문에 부적합하다.
- (다) 🔍 `ok` 를 `and` 로 이은 이유는 무엇인가요? `or` 로 이으면 회선 B 의 판정이 어떻게 달라지나요?
  - 쓸 내용: ① `and` 로 이은 이유 ② `or` 로 이으면 B 의 판정이 어떻게 달라지는지
  - 답: 지연, 지터, 손실의 세 가지 조건을 모두 만족해야 적합하기 때문이다. or로 이으면 조건 중 하나만 만족해도 적합으로 판정하므로, 지연 기준을 만족하는 회선 B가 잘못 적합 판정을 받게 된다.
- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(어느 회선이 되고 안 되는지, 이유 한 가지)
  - 답: 회선 A는 화상회의에 적합하지만, 회선 B는 지터가 크고 회선 C는 패킷 손실률이 높아 적합하지 않습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: if문을 사용하지 않고 and 조건을 파라미터값에 지정하면 True/False 값이 그 변수에 저장됨.

### 2. 세 숫자 판정 — 문제 6-2

- 세 회선의 판정과 걸린 기준을 적고, 세 숫자의 차이를 정리해 주세요.
  - 쓸 내용: ① A · B · C 의 판정과 걸린 기준 ② 지연 · 지터 · 손실이 각각 무엇을 나타내는지
  - 답: 
 
  ① A · B · C 의 판정과 걸린 기준: 평균 지연 150 ms 이하, 지터 30 ms 이하, 손실률 1 % 이하
  
  ② 지연 · 지터 · 손실이 각각 무엇을 나타내는지
    - 지연: 데이터를 보냈을 때 응답이 돌아오기까지 걸리는 시간. 숫자가 클수록 응답 늦음.
    - 지터: 응답 시간이 얼마나 들쭉날쭉한지를 나타내는 숫자. 화상회의에서 레이턴시 낮더라도 지터가 크면 말이 끊길 수 있음.
    - 손실: 보낸 데이터 중 응답이 돌아오지 않은 비율. 손실이 발생하면 데이터가 도착하지 않아 음성이나 영상이 끊길 수 있음.

### 3. 지연 원인 — 문제 7-1 · 7-2

- SaaS 접속이 느린 원인 구간과 그 근거를 적어 주세요.
  - 쓸 내용: ① 원인 구간 ② 근거(tracert 에서 뛴 값) ③ 사내 구간이 정상이라는 근거
  - 답: 

    - 원인 의심 구간: 4번 홉과 5번 홉 사이의 해외 연결 구간
    - 근거: tracert에서 4번 홉은 6ms였지만, 5번 홉에서 48ms로 급증했다. 이후 6번 홉은 49ms, 7번 홉은 50ms로 높은 지연시간이 유지됐다.
    - 사내 구간이 정상이라는 근거: 1~4번 홉의 응답 시간은 1~6ms로 낮게 유지됐다. 따라서 사내 구간보다는 통신사 또는 해외 연결 구간에 원인이 있을 가능성이 높다.

  - 쓸 내용: ① 알 수 없는 것(예: 한 시각의 값이라는 점) ② 다음 확인(시간대를 바꿔 다시 재기 · 구간 운영자에게 확인 요청)
  - 답:
    - 알 수 없는 것: 한 번의 측정 결과만으로는 일시적인 지연인지 지속적인 문제인지, 실제 원인이 어느 장비나 구간에 있는지 확정할 수 없다.\
    - 다음 확인: 다른 시간대에 ping과 tracert를 반복 측정해 결과를 비교하고, 지연이 계속되면 해당 구간을 담당하는 통신사 또는 외부 네트워크 운영자에게 측정값과 함께 확인을 요청한다.
