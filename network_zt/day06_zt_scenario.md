# A사 Zero Trust 적용 방안
## 5대 원칙 적용 방안
- ID: 모든 접속 경로에 MFA를 적용해 비밀번호만으로 로그인하지 못하게 한다.
- Device: 등록된 기기인지 확인하고, 보안 상태가 기준을 충족한 기기만 정산 시스템에 접속하도록 한다.
- Network: 서버 구역과 직원 PC 구역을 나누고, 필요한 포트만 연다
- Application: 재무팀은 SETTLE, 영업팀은 SALES에만 접근하도록 권한을 제한한다.
- Policy: 해외 접속, 새벽 접속, 대량 조회 등 위험 신호를 점수화해 추가 인증 또는 접속 차단을 적용한다.
## 판단과 집행
- PDP(결정): 계정의 재직 여부와 기기 등록 여부를 먼저 확인하고, 기기 보안 상태·MFA·접속 국가·접속 시간·조회 건수에 따라 점수를 계산해 허용·추가 확인·거부를 결정한다.
- PEP(집행): 정산 시스템 앞에서 PDP의 결정을 적용한다. 허용이면 접속시키고, 추가 확인이면 MFA를 요구하며, 거부이면 접속을 차단하고 기록한다.
## 흐름도
```
사용자 --요청--> PEP --문의--> PDP
                            |
                            v
                1. 재직 계정·등록 기기 확인
                2. 위험 신호 점수 계산
                3. 점수에 따라 결정
                    - 50점 이상: 거부
                    - 20점 이상: 추가 확인
                    - 20점 미만: 허용
                            |
                            v
사용자 <--결과-- PEP <--결정-- PDP

PEP 집행:
- 허용: 시스템 접속
- 추가 확인: MFA 요구
- 거부: 접속 차단 및 기록
```
## 최소권한 기준 (목록에 없으면 거부)
- 재무팀: SETTLE만 허용
- 영업팀: SALES만 허용
- 서비스 계정 batch-night: SETTLE에서 매일 02:00 정산 집계 작업만 허용
## 스코어링 결과
- 항목별 점수: MFA 10점 / 기기 5점 / 최소권한 15점 / 세그멘테이션 0점 / 위험기반인증 0점
- 총점: 30점 / 100점
- 먼저 올릴 항목과 이유: 기기 보안을 먼저 개선한다. 현재 기기 보안 점수는 5점이며, 사고 기록에서 등록되지 않은 기기 NB-7741로 정산 시스템에 접근한 사례가 있었다. 등록 기기 여부와 보안 상태를 확인한 뒤 접속을 허용하도록 개선한다.
